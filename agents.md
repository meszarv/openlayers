## Canvas Vector Rendering Chunking

- Rendering is budgeted at ~40 ms per frame, split into build (feature → instruction) and draw (instruction → pixels). Both phases use `frameTimings_` so overruns set `frameState.animate` and resume next frame (`src/ol/renderer/canvas/VectorLayer.js:46-154`, `2231-2285`, `839-970`).
- Build chunking: `prepareFrame()` keeps a `buildState_` with feature list and current index. It iterates features, calling `renderFeature()` until the 20 ms build slice expires, then stores progress and continues on the next tick. The map keeps displaying the previous executor until the new one is ready, with optional overlay feedback (`src/ol/renderer/canvas/VectorLayer.js:2173-2299`, `1500-1525`).
- Draw chunking: `renderWorlds()` tracks per-key `drawState` data (world, z-index, builder type, instruction index). If the draw budget is used up, it flags `frameState.animate` and picks up later, so large instruction sets do not block the UI (`src/ol/renderer/canvas/VectorLayer.js:434-704`, `839-970`).
- Image instructions are further chunked. `chunkStates` remember the last instruction index plus an adaptive `chunkSize`, and `computeImageChunkEnd()` ensures chunks end at geometry boundaries. After each slice, an exponential moving average of duration grows or shrinks the chunk size between 8 and 512 draw instructions, allowing OpenLayers to exploit idle frames but throttle when image drawing becomes expensive (`src/ol/renderer/canvas/VectorLayer.js:51-63`, `154-173`, `839-946`).
- Non-image builders (Polygon, LineString, Text, Default) still respect the frame budget because `renderWorlds()` re-evaluates after each builder/z-index/world loop, ensuring long but lightweight instruction batches can be paused between iterations (`src/ol/renderer/canvas/VectorLayer.js:795-985`).
